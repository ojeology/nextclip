## 1. Executive summary

The site is technically healthy and **every indexed URL survived the merge**. The blocking
AdSense work is no longer plumbing — it is **consent (CMP)** and **content composition**.

Three things changed the picture today:

1. **The flagship property had no ad disclosure at all.** All five ecosystem desks
   (tech, home, sports, entertainment, fitness) carried a proper Google AdSense
   paragraph. **Writers — the site root, 509 of 2,032 indexable pages, where a reviewer
   lands first — did not.** Worse, its privacy policy affirmatively claimed
   *"BRYME deliberately loads no third-party fonts, scripts, trackers or embedded
   widgets… enforced by an automated check."* That has been false since the AdSense tag
   went live. **Fixed (§2.1).**

2. **No consent management platform exists anywhere on the site.** Zero matches for
   consent/CMP/Funding Choices/OneTrust/Cookiebot on any live page. Since 16 Jan 2024
   Google requires a *certified* CMP for personalised ads in the EEA/UK, and **since
   1 March 2026 the TC string must be TCF v2.3** — a v2.2 CMP gets ad requests defaulted
   to "Limited Ads". This is the largest remaining gap. **P0 (§4).**

3. **49% of indexable pages belong to paused desks.** Entertainment alone is 846 pages
   (41%), sports 111, fitness 45 — all three paused under the production directive.
   Google's heaviest 2026 scrutiny falls on scaled/templated content, and the most common
   rejection reason is "Low Value Content". This is a **strategic** risk, not a bug. **P1 (§5).**

## 4. P0 — must finish before submitting to AdSense

### 4.1 Implement a Google-certified CMP
- Requirement is **not optional**: without a certified CMP, Google stops personalised ads
  for EEA/UK users and can limit serving entirely.
- **Must be TCF v2.3** as of 1 Mar 2026 and pass **Consent Mode v2** signals
  (`ad_storage`, `ad_user_data`, `ad_personalization`, `analytics_storage`) *before* the
  AdSense tag fires. A plain cookie banner does **not** satisfy this — it produces no TC
  string.
- Free tiers exist among certified providers (e.g. Enzuzo, CookieYes, Termly, iubenda);
  Gold-tier partners have the deepest integration. Pick from Google's official CMP list.
- **Implementation constraints specific to this repo:**
  - The CMP script must be added to `AD_HOSTS` in **both** `scripts/validate-browser.js`
    and `scripts/validate-contrast.js`, or gates 3 and 4 will fail on "unexpected
    scripts" / "third-party resource" across all render cases. **Do not** add
    `www.google.com`.
  - `scripts/validate-site-quality.js:56` blocks a fixed list of networks — confirm the
    chosen CMP host is not caught by it.
  - Production CSP is `script-src 'self' https:`; the CMP origin must be allowed.
  - The CMP must load **before** the AdSense loader in `<head>`, or consent signals race
    the tag.
- Then update all six privacy pages to name the CMP and describe the consent flow
  (currently they say consent "will be asked for" — that becomes true).

### 4.2 Owner-only: Google Search Console

authoritative answer to "are my pages actually indexed" — the live 200-crawl proves the

## 6. P2 — sequencing and hygiene

1. **Do not place ad units until approval.** Current state (verification tag live, no
   units) is correct and is now disclosed accurately on all six privacy pages. When units
   are wired, update the privacy pages again — they currently promise "this page will be
   updated before that changes."
2. **`npm run build` swallows generator failures.** The chain ends in
   `|| echo 'build: regeneration unavailable…'`, so a crashed generator still exits 0 and
   can produce a *false* determinism pass. Replace with a hard failure (or emit a marker
   the CI step greps for). Today's build was verified clean by grepping the log for
   `RuntimeError`/`Traceback` — that manual step should not be necessary.
3. **`bryme.onrender.com` unindexing.** The host is dead; all links are removed. Cannot be
   forced from here — IndexNow/Bing acknowledge-then-discard pings for a dead host, the
   Bing sitemap ping endpoint is deprecated (410), and the key file 404s. Removal happens
   by natural 404 recrawl, plus the owner using **Bing Webmaster Tools → URL removal**.
4. **GitHub Pages is disabled but a homepage is still set.** Harmless; tidy up.
5. **Repo is ~965 MB.** Slows clones and CI. Candidate for pruning large committed
   artifacts / `reports/` history.
6. **`content/make-money-articles.json` is dead data.** No builder reads it. Either wire it
   up or delete it so it cannot be mistaken for live content.

7. **`build-ecosystem.py` is deterministic, but CANNOT join the build chain — Render runs Python < 3.12.**
   It was excluded from `npm run build` and marked do-not-run because it read the wall
   clock. Root cause found and fixed: a single `_dt.date.today()` in the *"Counts verified
   at every build (last: …)"* stamp, which appears in exactly 2 files
   (`ecosystem/hub/index.html`, `public/index.html`). It now uses a `_build_now()` helper
   that honours `SOURCE_DATE_EPOCH`, matching the pattern already in
   `build-writing-first.py` and `build-routing.py`.

   Proven, not assumed:
   - Two pinned runs → **byte-identical** output.
   - Pin set to 2026-03-15 → stamp reads `2026-03-15`; pin unset → stamp reads today's
     real date. So the pin is genuinely honoured **and** production behaviour is unchanged.
   - Control run of the *original* script produced the **same 11-file diff**, confirming
     the change is behaviour-preserving.

   **The 11-file diff was never a real blocker.** Running the script standalone rewrote 11
   `ecosystem/entertainment/` pages, changing `href="/entertainment/"` to
   `href="/entertainment/browse/"` — but `build-routing.py` *already* sweeps exactly that
   across `ROOT.rglob("*.html")`. It simply never got the chance to run after the ecosystem
   builder, because the ecosystem builder was not in the chain. Placing it **first** lets
   routing normalise its output and the 11-file diff disappears. **No paused-desk page needed
   editing.**

   **But a third blocker is real and is NOT fixed: the script does not parse on Python < 3.12.**
   It was added to the chain at position 1, every local check passed, and the Render deploy
   then failed in 19 seconds:

   ```
   File "/opt/render/project/src/scripts/build-ecosystem.py", line 1883
     </div></main>{foot("sports")}TRIPLE-DOUBLE-QUOTE
   SyntaxError: f-string expression part cannot include a backslash
   ```

   (The line ends in three double-quote characters, closing the f-string; written out long
   here because they would otherwise close the fence.)

   That restriction was lifted by **PEP 701 in Python 3.12**. This workspace runs 3.13.14,
   where the file parses cleanly — which is why the build exited 0, all four gates were green
   and two pinned rebuilds were idempotent, while Render's older interpreter could not even
   read the file. **A local green run cannot catch a parse error when the local interpreter is
   newer than production's.** Reverted in `4092ef7e81`; Render went `live` again within ~40 s.

   There was **no outage**: Render keeps the last good deploy serving while a build fails, and
   the live site answered 2,032 / 2,032 sitemap URLs with HTTP 200 throughout.

   **Lesson for this repo:** before adding any script to `npm run build`, check it against the
   *deploy* interpreter, not just the local one — pin `PYTHON_VERSION` in `render.yaml`, or
   parse-check on the Render Python version. Until then `build-ecosystem.py` stays out of the
   chain and Home & Property pages remain committed static output. To be precise about what
   this does and does not block: it prevents **regenerating** home pages through the gated
   path, but it does **not** block the six Home tools — those already exist as committed
   static output plus plain JS assets and can be edited and shipped without running the
   builder (§5.2 was corrected on 22 Sep 2026 after a re-audit found all six live). The
   mortgage fix in §5.2 was made exactly that way.

   The only residual drift was four files whose dates disagreed with the tree: root
   `sitemap.xml`, `home/sitemap.xml`, `writers/sitemap.xml` and `index.html` carried
   `2026-09-21`, while `public/sitemap.xml` — the file CI pins the build date *from* —
   already carried `2026-09-22`. That inconsistency pre-dated this work; the old chain never
   rewrote the root copies, so nothing caught it. Verified **date-only**: normalising every
   `YYYY-MM-DD` to a placeholder makes old and new byte-identical for all four.

   What *was* proven locally, and remains true if the Python floor is ever raised:
   - two consecutive pinned builds are **idempotent** (`git diff --exit-code` = 0)
   - allowlist 509 → 509 and 2,032 → 2,032, **0 removed / 0 added**
   - sitemap `<loc>` union 2,038 → 2,038, **0 removed / 0 added**
   - all four gates green (1,527 render cases, 824 AA pairs, 0 failures)
   - the four normalised dates fixed a genuine inconsistency: root `sitemap.xml`,
     `home/sitemap.xml`, `writers/sitemap.xml` and `index.html` said `2026-09-21` while
     `public/sitemap.xml` — the file CI pins the build date *from* — said `2026-09-22`.
     Verified date-only: normalising every `YYYY-MM-DD` to a placeholder makes old and new
     byte-identical. **These four dates were kept**; only `package.json` was reverted.

   **Path to gated regeneration of Home & Property pages** (owner decision, pick one) — note
   this is about CI coverage for those pages, not about the tools existing:
   - **(a)** Raise Render's Python to ≥ 3.12 (`PYTHON_VERSION` env var) and re-land the chain
     change. Smallest code change, but shifts the runtime for every generator — so it needs a
     full re-verification of all nine, not just this one.
   - **(b)** Rewrite the PEP 701 f-strings in `build-ecosystem.py` so it parses on the current
     Render Python. Contained in principle, but it touches a 5,415-line generator that produces
     paused-desk pages, and every rewritten f-string is a chance to change output silently.
   - **(c)** Leave the builder out of the chain and author Home tools as committed static
     output. **This is the current state, and it works** — the §5.2 mortgage fix shipped this
     way with no deploy risk. The cost is that those pages get no CI verification, which is
     precisely how the root `feed.xml` 404 shipped in the first place. If (c) is kept, the
     mitigation in §5.2 now covers it: `scripts/validate-home-tools.js` runs in `npm test` and
     proves all six tools still parse, mount and render inputs, without needing Playwright.

   Recommendation: **(a)**, with the Python floor pinned explicitly in `render.yaml` so the
   local and deploy interpreters cannot drift apart again. That single env var is also what
   would have prevented this failure.


8. **`_age()` in `build-ecosystem.py` has always returned `None` (found, not fixed).**
   `datetime` and `timezone` are never imported at module level — the only datetime imports
   are function-local aliases (`_dtt`, `_dt`, `_dtc`). So line ~2380 raises `NameError` on
   every call and the bare `except Exception` swallows it. Reproduced standalone:
   `_age("1998-05-04")` → `NameError: name 'datetime' is not defined` → `None`.

   Effect: squad rows never render their `"NN yrs"` suffix, only the position. Left as-is
   deliberately — fixing it adds ages to every player row on the **paused** Sports desk,
   which needs an owner decision, not a drive-by edit. Documented at the call site. When it
   is fixed it **must** use `_build_now()`, not `datetime.now()`, or ages will drift daily
   and re-break reproducible builds.

   This is also a warning about the codebase's error handling: a bare `except Exception`
   turned a hard bug into eight months of silent wrong output. Same failure mode as item 2
   (`|| echo` in the build) — both swallow errors that should be loud.
