# BRYME Tech — Living-Hub Roadmap (2026-09-24)

**Owner brief:** *"Make the tech niche an 11/10… build the tech website into a tech hub… rebuild the display but preserve all URLs — no URL changes must be made… the tech niche hub should be like a living machine… build an addiction tech hub."*

This document records **what shipped on 24 Sep 2026** and the **staged roadmap** that turns the rebuilt hub into the compounding, habit-forming technology desk the brief asks for. Every claim below is backed by a gate that runs in CI.

> Governing constraint, honoured throughout: **the URL surface is immutable.** The desk publishes and links **320 unique `/tech/` URLs**. The rebuild changed only *presentation and behaviour* on those URLs. That is machine-verified by `reports/tech-hub-2026-09-24/diff-urls.py`, which diffs the pre-rebuild (`HEAD`) URL set against the working tree and fails the build on any addition, removal, or canonical change. It prints: `baseline 320 / current 320 / added 0 / removed 0 / canonical mismatches 0`.

## 0. What "the living machine" is (shipped 24 Sep)

The hub at `/tech/` is no longer a chronological feed. It is a **single self-describing index of the whole desk** that re-routes itself around what a visitor came to *do*. It is generated by one shared renderer (`scripts/tech_hub_render.py`) invoked from `build-ecosystem.py:tech_pages()`, so the generator and the refresh path can never drift.

**The display (what you see):**
- **Boot / readout band** — edition line, one H1 ("Practical technology. No theatre."), and six **live gauges** counted from the catalogue at build time, not invented: pieces, sections, browser tools, comparisons, diagnostic trees, first-hand builds. Currently `258 / 12 / 16 / 62 / 14 / 8`.
- **Memory band** — *Saved for later* and *Continue reading*, furnished from `localStorage` by a tracker that runs on every `/tech/` article. Nothing is uploaded; clearing site data clears it.
- **Need router** — six jobs (Fix what broke / Lock it down / Compare two things / Choose what to use / Build and ship it / Understand a thing). Picking one re-sorts the index to that job. Keyboard `1–6`.
- **The core** — every published piece in the page as a linkable row (title + one-line dek + kind badge + date + Save), grouped into shelves, collapsible per shelf, with an instant filter, kind chips, saved-only, A–Z / recently-verified sorting, and a random deep cut.
- **Toolbox, section shelves, and a "read the machine" band** — self-read honesty: the freshest date the desk carries, the shelves that are still thin (<10 pieces), and the standing rules (no benchmark we didn't run, no pricing without a dated source, no fake winners).

**The behaviour (what it does):** instant client-side filtering over all 258 rows; a command palette (`Ctrl/⌘+K` or the on-page button); save-for-later; the tracker; sorting; the deep cut; and reveals on scroll. All behaviour lives in `assets/tech-hub.js` (ES5, `defer`, no inline JS — the family ships `script-src 'self' https:`), styles in `assets/tech-hub.css`. Both are additive: **with JavaScript off, the hub is still a complete, un-clipped index** — the no-JS gate asserts zero hidden rows, no dead toolbar, and no horizontal overflow.

**Honesty by construction — "addiction" is utility, not dark patterns.** The pull comes from a machine that gets more useful on every visit (it remembers what you saved and read, and flags pieces verified since your last visit). There are no streaks, no guilt counters, no fake urgency, no hidden close button, and no telemetry that leaves the device. The hub says out loud that sorting is by keyword and that the thin shelves are what we build next.

Mitigations already in place: `content-visibility:auto` per shelf so low-end phones skip offscreen layout, capped deks, badges only where informative, and a single deferred script. The no-JS and overflow gates keep it honest on small screens.

## 2. The compounding loop (why it becomes habit-forming)

The machine is designed to make the second and tenth visit *measurably* better than the first:

1. **Visit N:** you filter/solve, save a few pieces, read one. The tracker records it.
2. **Visit N+1:** *Continue reading* resumes you; *Saved for later* is your queue; pieces verified since visit N carry a **NEW** flag; the filter state you left is restored. The desk has become yours.

That is the whole addiction thesis: **return value compounds**, and every loop runs on-device with zero surveillance.

## 3. Staged roadmap (next 90 days)

Sequenced so nothing here ships before the loop is proven. Each phase ends with one IndexNow ping and the full gate suite.

### Phase 1 — Prove the loop (weeks 1–2) · *no new URLs*
- **Instrument the machine, privately.** Add an opt-in, on-device "about my desk" readout (counts from `localStorage`) so we can watch the loop without shipping analytics we don't have. No server telemetry.
- **Thin-shelf closure sprint.** The self-read band lists shelves under 10 pieces (e.g. streaming, smart-home). Build those to ≥10 first — the hub already advertises them as the queue.
- **Freshness engine.** Wire the rolling re-verification cadence (Section 12 of the master brief: 90d for pricing/vendor, 6mo comparisons) into the gauges so "swept <date>" moves on its own.
- **Exit criteria:** the NEW-since-last-visit flag and *Continue reading* render for returning visitors in ≥ the no-JS and reduced-motion cases; zero URL change.

### Phase 2 — Make the desk a product (weeks 3–6)
- **Comparison matrix.** `/tech/` already counts 62 comparisons. Add a client-side matrix view (rows = products, cols = the documented trade-offs) that links to the existing comparison pages — display only, no new routes.
- **Deepened search-as-product.** Upgrade the palette to tolerate one typo (subsequence/Damerau-light) and surface the matched words, still 100% client-side over the in-page index.
- **Saved export.** Let *Saved for later* copy a plain-text reading list to the clipboard (device-only), turning the queue into something shareable.

### Phase 3 — Habit at scale (weeks 7–12)
- **Reader rhythm, not streaks.** A calm "your last 3 visits" recap and a weekly "what changed on the desk" list generated from real `dateModified`s — never a guilt counter.
- **Section hubs adopt the machine.** Port the same renderer shell (needs → index → self-read) to the 12 section pages, so the whole desk feels like one instrument. *Display-only; URLs unchanged.*
- **Monetisation on-ramp.** When the owner says go, wire `_ads_slot()` with the discipline in `docs/ADS.md` (ads never resemble Save buttons or rows; the contrast/motion gate keeps them honest).

### Standing rules that never change
- No URL is created, renamed, removed or redirected by any hub work (the diff gate enforces this).
- No fabricated number appears on the hub; every gauge and readout is counted at build time.
- No behaviour regresses the no-JS, reduced-motion, contrast, or overflow gates.
- No dark pattern: everything the machine remembers is the visitor's, on the visitor's device.
